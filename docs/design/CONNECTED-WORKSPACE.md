# Connected model workspaces

The portable model pages share a chapter sidebar and a selected-operator workspace. Architecture, Training, Serving and Evidence remain distinct lenses. Hardware, Networking and Data Representation remain shared destinations.

The module registry connects exact scene node identities to existing teaching implementations. Available panels are derived from those bindings: Schematic, Maths, PyTorch, Worked example and Sources. An unrelated model or an unclassified node cannot gain Python coverage because its name resembles an example. The selected node ID, panel and CPU fixture/step are persisted as `module`, `panel` and `example` in scenario state. Existing stages and URLs remain compatible. Invalid identifiers and unavailable panels resolve to actual scene defaults.

Inputs and outputs in the inspector follow authored logical edges. Retained-state inputs are not automatically described as reused state. The original equation, shape and ownership records remain authoritative. Module identities organize explanation; they do not introduce architectural facts.

Detailed chapter explanations remain available under the chapter reference disclosure beneath the schematic. Module panels bring the related mathematics, canonical Python and CPU-produced values into the same workspace. Print expands reference disclosures. This replaces the former requirement that every code listing and worked example occupy the default vertical reading flow.

Hugging Face publisher configurations and available publisher code establish checkpoint baseline identity. Transformers library implementations remain labelled separately. Serving uses scoped SGLang/vLLM references. Training uses Megatron mechanisms where applicable, without claiming a publisher training recipe. Exact checkpoint runtime support is not inferred from a family implementation. See IMPLEMENTATION-SOURCES.md for inspected symbols and gaps.

Desktop uses a compact header, chapter sidebar, scrollable schematic and adjacent inspector. Below 1200px the inspector stacks; below 900px chapter navigation becomes a keyboard-accessible drawer. Fonts are local system fonts; no runtime assets are downloaded. Tensor dimensions never contain thousands separators.

The portable build also compresses the stylesheet and restores its exact UTF-8 bytes into the inline style element before the application initializes. This uses the same native gzip decompression already required for source/scene payloads and keeps the existing portable-file size limit without reducing diagram detail or typography.

Unreviewed manifest migration in this change binds the new navigation defaults and workspace renderer modules. The changed local consumers are sanitizeState, application/core/model/style files, the build and HTML shell. Mathematical functions and scene contracts are unchanged. No accepted source bytes, signed subjects, reviewer identities or runtime receipts are rewritten; fingerprints establish local identity only.

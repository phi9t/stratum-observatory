# V4.1 module schematics

Each canonical Python example has a detailed scene in the existing canvas, using the
same operation nodes, orthogonal dependency wires, state colors and inspector as the
layer diagrams. The module inventory comes from `PYTORCH_EXAMPLES`; shared helpers
are explained inside their owning example. This covers mHC/flat CED orchestration,
MoE, Engram, compression, sparse selection, target attention, draft attention,
Markov/confidence heads and the separately scoped DeepSpec verifier.

Readers open an example through **Inspect module schematic** or the **Module schematic**
selector. The scene's URL, exported scenario and SVG identify that module. The Python
record is expanded below the schematic; chapter-return controls retain the chapter
narrative. A module view is offered only for V4.1. Unknown module states are rejected
by the normal state sanitizer.

These scenes use focal stages so existing browser, schematic, aesthetic, presentation,
source-consumer and preview inventories visit every module. The module registry must
be exhaustive: a missing builder throws. Every node carries source links and explains
its tensor contract. Quantities come from the checkpoint record or symbolic dimensions
of the reference code. Distributed implementation, checkpoint parity and runtime
certification are outside the examples' scope.

The new scene and file identities depend on the existing source-anchored Python
records; new identities do not approve scientific claims. Existing accepted source
bytes, review records and trust roots are unchanged.

The training reference has an explicit ambiguity: prose on Ultra-Scale line 477 describes an additional FP32 gradient copy, while its displayed equations on lines 484–488 list BF16 weights and gradients, FP32 master weights, and FP32 Adam moments. The registered method follows those displayed categories, totaling 16 bytes per parameter before sharding; an extra FP32 gradient buffer and peak live memory are excluded. It does not assert that all frameworks allocate those categories identically.

The ring section describes both directions colloquially as “to and from”. Its ReduceScatter/AllGather steps imply `2*(N-1)/N` payload bytes sent per rank and the same quantity received separately. STRATUM labels the sent-byte accounting explicitly; adding received bytes would double a different metric. Roofline limits likewise remain analytical ceilings, never runtime measurements. GQA projection and cache identities apply only to ordinary GQA layers; MLA, QSA and recurrent state require their own model-specific ledgers.

The prose rounds this to 6.7 GB, while a table labels the same numeral GiB. The example registry preserves both published values and the independently derived conversion. This is an explained source-unit discrepancy, not a reproduction of the table as a correct binary quantity. Its publication claim is derived from the cache method and carries exact selectors for both the equation and table label.

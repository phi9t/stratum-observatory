## Exact implementation map

**Verification is publicly implemented, with limited model scope.** [deepspec/eval/base_evaluator.py:186–305](https://github.com/deepseek-ai/DeepSpec/blob/005e03b81cec38b7da6399833d609ee89a2587f2/deepspec/eval/base_evaluator.py#L186) defines `verify_draft_tokens`: target evaluation consumes anchor plus proposed prefix; it gathers target/draft probabilities at proposed token IDs, clamps the draft denominator at `1e-8`, accepts via `min(1,p/q)`, and uses cumulative product of acceptance indicators to retain only the first uninterrupted prefix. On rejection it samples a residual correction; if all survive, it samples the target bonus distribution. [deepspec/eval/base_evaluator.py:308–441](https://github.com/deepseek-ai/DeepSpec/blob/005e03b81cec38b7da6399833d609ee89a2587f2/deepspec/eval/base_evaluator.py#L308) defines `generate_decoding_sample`, explicitly restricted to batch size one. It commits accepted tokens plus correction/bonus, advances `start`, and crops target cache to the new start. An accepted stop token ends generation without committing the bonus.

**Residual correction.** [deepspec/utils/sampling.py:6–44](https://github.com/deepseek-ai/DeepSpec/blob/005e03b81cec38b7da6399833d609ee89a2587f2/deepspec/utils/sampling.py#L6) defines `sample_residual`: normalize positive part of target minus draft probabilities; if residual mass is tiny, fall back to target probabilities. `logits_to_probs` uses a one-hot argmax at near-zero temperature, otherwise temperature-scaled softmax. This is actual executable reference logic, not a guarantee of identical floating-point behavior in production.

**Draft cache is separately cropped.** [deepspec/eval/dspark/draft_ops.py:22–46](https://github.com/deepseek-ai/DeepSpec/blob/005e03b81cec38b7da6399833d609ee89a2587f2/deepspec/eval/dspark/draft_ops.py#L22) (`forward_dspark_draft_block`) projects current target features, runs non-causal draft attention, then crops draft KV to `start`, removing speculative draft positions while retaining prior context. [deepspec/eval/dspark/evaluator.py:134–147](https://github.com/deepseek-ai/DeepSpec/blob/005e03b81cec38b7da6399833d609ee89a2587f2/deepspec/eval/dspark/evaluator.py#L134) (`Qwen3DSparkEvaluator._update`) carries only `accepted_draft_tokens + 1` target feature positions into the next cycle. The extra position includes the old anchor. Target/draft caches are distinct; do not draw a shared KV store.

**Public confidence threshold differs from production scheduling.** [deepspec/eval/dspark/draft_ops.py:82–153](https://github.com/deepseek-ai/DeepSpec/blob/005e03b81cec38b7da6399833d609ee89a2587f2/deepspec/eval/dspark/draft_ops.py#L82) computes confidence logits, applies sigmoid, and truncates at the first per-position confidence below a fixed threshold. A nonpositive threshold keeps the entire block. This is neither cumulative-confidence thresholding nor a load-aware throughput optimizer. [deepspec/eval/dspark/confidence_head.py:345–375](https://github.com/deepseek-ai/DeepSpec/blob/005e03b81cec38b7da6399833d609ee89a2587f2/deepspec/eval/dspark/confidence_head.py#L345) (`ConfidenceHeadRecorder.observe`) separately forms cumulative products for reliability diagnostics. No profiled SPS lookup or multi-request scheduler appears in the inspected implementation.

**Sequential head.** [deepspec/modeling/dspark/markov_head.py:8–89](https://github.com/deepseek-ai/DeepSpec/blob/005e03b81cec38b7da6399833d609ee89a2587f2/deepspec/modeling/dspark/markov_head.py#L8) (`VanillaMarkov`) learns vocabulary-to-rank embeddings and rank-to-vocabulary projection. `sample_block_tokens` adds preceding-token transition bias to each base-logit vector, samples left-to-right, and preserves corrected logits for verification probabilities. Optional gated and RNN variants are additional research choices, not evidence that V4.1 uses them.

**Raw confidence and training.** [deepspec/modeling/dspark/qwen3/modeling.py:292–307](https://github.com/deepseek-ai/DeepSpec/blob/005e03b81cec38b7da6399833d609ee89a2587f2/deepspec/modeling/dspark/qwen3/modeling.py#L292) concatenates hidden state with preceding-token Markov embedding when configured; [deepspec/modeling/dspark/common.py:43–49](https://github.com/deepseek-ai/DeepSpec/blob/005e03b81cec38b7da6399833d609ee89a2587f2/deepspec/modeling/dspark/common.py#L43) (`AcceptRatePredictor`) returns a linear scalar, not an internally sigmoid-transformed probability. [deepspec/modeling/dspark/loss.py:60–70](https://github.com/deepseek-ai/DeepSpec/blob/005e03b81cec38b7da6399833d609ee89a2587f2/deepspec/modeling/dspark/loss.py#L60) derives the soft acceptance target from total variation distance; `_collect_local_terms` at lines152–179 uses detached soft targets and binary cross entropy with logits. Thus “raw head logits” and “sigmoid probability used by evaluator” are separate stages.

## Paper-only scheduler details

[Paper v1 §§3.2.1–3.2.2, Algorithm 1, §5.2](https://arxiv.org/html/2607.05147v1) describes sequential temperature calibration of cumulative survival estimates. Algorithm 1 ranks prefix survival probabilities across requests and scores expected accepted tokens times profiled steps per second. It stops at the first throughput non-improvement, avoiding future-token selection bias; optimality requires unimodality. Production instead determines capacity using confidence predictions from two steps earlier, ranks current proposals using current confidence, and searches historical capacities without early stopping to accommodate jagged hardware curves. These are distinct scheduling regimes, not interchangeable implementations. The paper's production experiments concern V4 Flash/Pro preview; its offline Qwen/Gemma evaluation disables scheduling. None establishes V4.1 Flash production behavior or a locally reproduced speedup.
